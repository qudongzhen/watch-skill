# 笔记写作契约

这份文档写给**动手写 `note.md` 的人（或模型）**。取证脚本已经跑完，图版和转写都在
`notes/<slug>/` 里。目标是把"证据"变成"人能用的学习笔记"。

## 一、成品长什么样

一份 `note.md`，中文，**正文 800 字起，上限 1800 字（不含附录）**；分章超过 8 节时按每节 +160 字放宽
（10 节约 2200）——章节越多，允许写得越长。结构固定：

```
# <视频标题>
> 一句话结论：这段视频讲了什么、对谁有用。

**来源** <链接>　**UP 主** …　**时长** …　**取证时间** …

## 大纲
1. 00:00 开场：<这一节在讲什么>      ← 时间戳一律写成 mm:ss 并在括号里给跳转链接
2. 03:12 …

## 分章要点

### 00:00–03:12｜<小标题>
- 要点（每条一句话，动词开头，别写"讲了…"）
- 要点
![第 1 段](assets/stills/s01_00096.png)      ← 优先用全屏截图（图版上的字不可采信）
> 证据：第 1 行第 2 列（03:12），第 2 行第 1 列（05:40）

### 03:12–…

## 关键概念 / 术语
| 概念 | 一句话解释 | 出现位置 |

## 可直接使用的结论 / 待办
- [ ] …

## 置信度与缺口
- 高置信：…
- 待核实：…（说明为什么没核：无字幕、画面模糊、未看原片）
- 未做：…

## 附录：取证说明
（**抄 BRIEF.md 里「取证说明」那一节**，别自己算：素材规格、图版形状、段内间隔、截图数、转写段数）
```

> 关于配图：**每章一张图，优先用 `assets/stills/` 的全屏截图**（图版每格才 150–250px 宽，
> 读不了字）。图版是写作者自查覆盖用的草稿，不是交付物——8 篇既有笔记的 53 处图片引用里，
> 只有 2 处是图版。要核对某一步的细节，用 `pipeline/zoom.py` 要一张 0.3–1 秒/帧 的密集图版，
> 别把它贴进正文。

## 二、四条硬规则

1. **图版里的文字一律不采信。**
   实测过：3×3 图版里同一个小字被"读"出九个不同值；还有一次读出了一组画面上根本不存在的
   标题。分辨率不够时，视觉会**渲染一个合理内容**，而不是报告"读不到"。
   → 要把原文写进笔记，先用 `pipeline/still.py <slug> --at <秒> --crop x,y,w,h --zoom 2`
   放大看图，再抄。

2. **时间映射只信 manifest。**
   "第几行第几列 = 第几秒"见 `assets/grids/*/manifest.json`；图里烧的帧号只供人眼核对。
   写"第 2 行第 1 列"时必须同时写秒数，读者才能验。

3. **每条结论都要能回溯。**
   结论 → 时间戳 → 哪张图版哪一格。回溯不了的推断，写进"待核实"，不要混进正文。

4. **不过度取证。**
   人看视频会自动忽略光标闪烁、控件微动 15 像素这类事。量测数字（切点、运动量、冻结段）
   属于附录，不属于正文。

## 三、三类常见素材的写法差异

| 素材 | 笔记重心 | 特别注意 |
|---|---|---|
| 讲座 / 口播 | 论点和论证链 | 转写是主证据，但同音错字要按上下文改，并在附录列出改了什么 |
| 教程 / 录屏 | 可复现的步骤 | 每步要"画面里能看到的操作"，别写"然后配置一下" |
| 评测 / 产品 | 结论与依据 | 数字和时间点必须对得上画面，别用印象补细节 |

## 四、转写怎么用

- `research.json` 的 `asr` 数组是**校正后**的文本（繁转简 + 词表替换都已算进去），
  不等于 whisper 原稿；要引用"机器原话"看 `evidence/transcript.md`（原稿不会被覆盖）。
- 有画面证据时以画面为准；两者冲突时，正文写校正后的，附录并列机器原文。
- **改字不要靠手感**：这一集的专有词写进 `notes/<id>/terms.json`（`{"寒暑": "setter"}`），
  跑 `pipeline/asrfix.py <id> --write` 会生成 `evidence/transcript.fixed.md` 并把改动计数写进
  `research.json.asr_meta`；`evidence/transcript.md` 保持机器原稿不动。
- 转写只用来**对齐内容与时间**，不要把整段转写贴进正文——笔记不是逐字稿。

### 引语要带出处（2026-10-30 新增）

引号在中文里既能引话也能强调，机器分不出来。所以写的时候把出处写出来：

| 写法 | 判断 |
|---|---|
| `「贵是贵点，但吃了不烧心」（00:12，字幕原文）` | ✅ 有时刻 + 有来源 |
| `图上的菜单写着「Import」（读屏）` | ✅ 明确是画面上的字 |
| `他说「中文要完了」` | ❌ 没时刻没来源，读者核不了 |
| `这属于"论证型短视频"` | ⚠️ 这是强调，别用引号，用**加粗** |

自查：`py -3.14 pipeline/quote_check.py <id>`，按「有出处 / 仅时刻 / 无出处」分类列出。
它**不判断真假**——真假只能回原帧看（`still.py --crop`）。

## 五、旧取证包还能不能用

取证包可能是几轮之前生成的（`research.json` 里没有 `pick` / `asr_meta` 就是老的）。规矩是：

1. **成品笔记不会被覆盖**：`run.py` 在 `note.md` 存在时改写 `research.new.json` / `BRIEF.new.md`，
   要覆盖得显式加 `--refresh-meta`。所以目录里出现 `*.new.*` 是正常的，不是失败。
2. **看到 `*.new.*` 先比差异**：它会打印"分段 8→8、图版 9→9 张（帧 97→153）"这类摘要。
   差异只涉及格数/帧数、且你不打算重写笔记时，**不要**覆盖——笔记附录里的采样口径会跟着变。
3. **老 `research.json` 缺字段是正常的**：`asr_meta` 缺 = 没跑过后处理；`stills[].pick` 缺 = 当年没选帧。
   不要为了让字段齐全而重跑，那些字段只影响"怎么说"，不影响"能不能引用证据"。

## 六、图文教程体例（`--style tutorial`）

教程类素材（录屏、软件演示、开发日志）不写"论证结构"，写**能照着做的步骤**。
判断标准只有一条：**读者不看视频，只看这篇笔记，能不能做出来。**

```
# <标题>
> 一句话结论：这个视频教你能做出什么。

**来源** …　**环境** Godot 4.x / Unity 6 …（版本写清楚，教程对版本敏感）

## 你将得到
（成品是什么，一句话 + 一张整体效果图）

## 前置条件
- 软件与版本 / 素材 / 前置知识

## 步骤

### 步骤 1｜00:56 让按钮有挤压感
要做什么：一句话。
![按钮缩放](assets/stills/s02_00096.png)
- **怎么做**：X 和 Y 分开补间，Y 稍晚；时长 0.15s，回弹用 Back。
- **怎么判断做对了**：按下时先扁后鼓，松手回正不抖。
- **坑**：直接等比缩放会像"放大镜"，没有形变感。

### 步骤 2｜…

## 自检清单
- [ ] 最长和最短的按钮都试过
- [ ] …

## 排错
| 现象 | 原因 | 处理 |
|---|---|---|

## 置信度与缺口
## 附录：取证说明
```

**教程体的额外硬规则：**

1. **每个步骤必须有一张图**，图要拍在"这一步的画面"上（`assets/stills/` 里已有按段抓好的全屏帧）。
2. 步骤标题固定 `### 步骤 N｜mm:ss 这一步做什么`，秒数用该步骤**开始**的时刻。
3. 每步给三样：**怎么做**（可执行动作）、**怎么判断做对了**（可观察结果）、**坑**。
4. 代码与参数**只写从全屏截图里真读到的**；读不清就写"画面太小，未展开"，不要补一个"合理"的值。
5. 版本、菜单路径这类信息错一个字读者就卡住——不确定就标"待核"。
6. 不写"多练练就好"这类空话；要么给判据，要么不给建议。

## 七、写完自检

先跑机器检查（形式与可回溯性），再人工过一遍：

```powershell
py -3.14 pipeline/finish.py <slug>     # 验收（= note_audit）+ 导出，一条命令
```

FAIL 必须清零；WARN 要能说清为什么留。只想看检查结果、不导出，用
`py -3.14 pipeline/note_audit.py <slug>`。

- [ ] 每个 `##` 小节都有时间范围
- [ ] 每张引用的图都在 `assets/` 里真实存在（相对路径）
- [ ] 没有一处结论缺少时间戳
- [ ] "置信度与缺口"写了，且没有把猜测写成事实
- [ ] 附录的采样口径是**从 BRIEF 抄的**，与该目录 `research.json` 对得上（格数、张数、间隔）
