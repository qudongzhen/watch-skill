# 笔记写作契约

这份文档写给**动手写 `note.md` 的人（或模型）**。取证脚本已经跑完，图版、截图和转写都在
`notes/<slug>/` 里。目标不是"把视频复述一遍"，而是**做出一篇别人能照着干、能核对、愿意留着的笔记**。

> 2026-11-11 起分两档规则：新取证包（`research.json` 里 `note_schema >= 2`）走本文件的"结构底线"，
> 不再限制字数；旧包沿用旧规则。差别只在**长度**，四条铁律两档一致。

## 一、成品长什么样

正文**不设字数上下限**：长度由内容决定——参数多的教程自然长，一个观点短片自然短。
底线是**结构与可回溯**：开头讲清、结尾留底、每张图有图注与出处、每条结论能回溯。

学习笔记体（`study`）：

```
# <视频标题>
> 一句话结论
**来源** …　**UP 主** …　**时长** …　**取证时间** …
## 大纲           ← 时间戳 mm:ss + 跳转链接
## 分章要点       ← ### 00:00–03:12｜小标题
## 关键概念 / 术语
## 可直接使用的结论 / 待办
## 置信度与缺口
## 附录：取证说明   ← 抄 BRIEF 的「取证说明」，别自己算
```

图文教程体（`tutorial`，见 §六）。两类共同的硬要求：

- 图必须**嵌在对应段落里**，不许集中在开头或结尾；
- **每张图下面一行图注，按内容手写**：`*图 N：这张图证明了什么、该看哪几个数（mm:ss）*`。
  Alt 文本只在图挂了时显示，读者平时看不见；**照抄 Alt、或写成"图 N：画面/截图（时间）"算不合格**——
  图注要回答"读者该从这张图里读出什么"，不是给图片起个名字。
- 正文里出现的时间戳要在片长内，且能对到某张图版/截图的覆盖区间；
- 带时间的**大纲条目与分章标题都要给跳转链接**（B 站 `?t=秒`），读者点了就回原片。

## 二、四条硬规则

1. **图版里的文字一律不采信。**
   实测过：3×3 图版里同一个小字被"读"出九个不同值；还读出过画面上不存在的标题。
   分辨率不够时视觉会**渲染一个合理内容**，而不是报告"读不到"。
   → 要把原文写进笔记，先用 `pipeline/still.py <slug> --at <秒> --crop x,y,w,h --zoom 2` 放大看过。

2. **时间映射只信 manifest。**
   "第几行第几列 = 第几秒"见 `assets/grids/*/manifest.json`；图里烧的帧号只供人眼核对。
   写"第 2 行第 1 列"时必须同时写秒数，读者才能验。

3. **每条结论都要能回溯。**
   结论 → 时间戳 → 哪张图（图版或截图）。回溯不了的推断，写进"待核实"，不要混进正文。

4. **不过度取证。**
   人看视频会自动忽略光标闪烁、控件微动 15 像素这类事。量测数字（切点、运动量、冻结段）
   属于附录，不属于正文。

## 三、三类素材的写法差异

| 素材 | 笔记重心 | 特别注意 |
|---|---|---|
| 讲座 / 口播 | 论点和论证链 | 转写是主证据，但同音错字要按上下文改，并在附录列出改了什么 |
| 教程 / 录屏 | **可复现的步骤** | 一步一件事；正文怎么读着顺怎么写（三段式可选）；参数只抄真读到的 |
| 评测 / 产品 | 结论与依据 | 数字和时间点必须对得上画面，别用印象补细节 |

## 四、转写怎么用

- `research.json` 的 `asr` 是**校正后**的文本（繁转简 + 词表替换都已算进去），不等于 whisper 原稿；
  要引用"机器原话"看 `evidence/transcript.md`（原稿不会被覆盖）。
- 有画面证据时以画面为准；两者冲突时，正文写校正后的，附录并列机器原文。
- **改字不要靠手感**：这一集的专有词写进 `notes/<id>/terms.json`（`{"寒暑": "setter"}`），
  跑 `pipeline/asrfix.py <id> --write` 会生成 `evidence/transcript.fixed.md` 并把改动计数写进
  `research.json.asr_meta`。
- 转写只用来**对齐内容与时间**，不要把整段转写贴进正文。
- **有硬字幕时**：BRIEF 会标"检测到硬字幕"，参数与菜单名以字幕原文为准（字幕是作者写的，
  比 ASR 准）；两者冲突时写字幕的，并在置信度里说明。

### 引语要带出处

| 写法 | 判断 |
|---|---|
| `「贵是贵点，但吃了不烧心」（00:12，字幕原文）` | ✅ 有时刻 + 有来源 |
| `图上的菜单写着「Import」（读屏）` | ✅ 明确是画面上的字 |
| `他说「中文要完了」` | ❌ 没时刻没来源，读者核不了 |
| `这属于"论证型短视频"` | ⚠️ 强调别用引号，用**加粗** |

自查：`py -3.14 pipeline/quote_check.py <id>`，按「有出处 / 仅时刻 / 无出处」分类列出。
它**不判断真假**——真假只能回原帧看（`still.py --crop`）。

## 五、查证：画面是证据，官方文档是准绳

不设"外部核实"必填小节，但有一条纪律：

- 参数含义、菜单路径、版本行为**描述不清或自相矛盾**时，去查官方文档（Blender Manual、Godot Docs 等）；
- 查到就就地写 `（依据：[Blender 手册 · Hair Curves](链接)）`；
- 与画面冲突时**正文按画面写**，并注明版本差异（"本片是 4.0 Alpha，手册现在写作 X"）；
- 查不到就写「未查到」，**不得**因为"应该是这样"而写成断言。

## 六、图文教程体例（`--style tutorial`）

判断标准只有一条：**读者不看视频，只看这篇笔记，能不能做出来。**

```
# <标题>
> 一句话结论：这个视频教你能做出什么

**来源** …　**环境** Blender 4.0.0 Alpha / Godot 4.x …（版本写清楚，教程对版本敏感）

## 你将得到
（成品是什么，一句话 + 一张整体效果图）

## 前置条件
- 软件与版本 / 素材 / 前置知识

## 步骤目录
| # | 步骤 | 时间 | 跳转 |
|---|---|---|---|
| 1 | 摆参考图 | 00:40–01:10 | [00:40](…?t=40) |

## 步骤

### 步骤 1｜00:40 摆参考图 [00:40](…?t=40)

`Shift+A → Image → Reference` 把照片导进来，`R` 绕 X 转 −90° 立起来，拖到球体左侧与头同高。
判据很直接：正视图里猫脸中线与球体中线重合，否则后面所有梳理方向都会偏。

## 参数总表
| 参数 | 值 | 出现位置 |
|---|---|---|

## 常见坑 / 排错
| 现象 | 原因 | 处理 |

## 自检清单
- [ ] …

## 置信度与缺口
## 附录：取证说明
```

**教程体的额外硬规则**：

1. **一步一件事**：一个操作、一组参数各成一步（判据可以并进叙述，不必单列）。
2. **正文不设模板**：段落、列表、表格都行，怎么读着顺怎么来。三段式（怎么做 / 怎么判断 / 坑）只是可选写法，不是必填。
   唯一要求是**开头讲清、结尾留底**：标题 + 一句话结论 + 来源环境；结尾有自检/排错、置信度、附录。
3. 步骤标题固定 `### 步骤 N｜mm:ss 这一步做什么`，秒数用该步骤**开始**的时刻，并带跳转链接。
4. 图嵌在对应步骤里，不要堆在开头或结尾。
5. **参数/代码步骤要给"看得清"的图**：全屏图在正文宽度下字通常只有 8px，读不了。
   用 `pipeline/crop.py` 找候选框、按需生成放大图（`--write`），并与全屏图放在同一步（先全屏、后放大）：
   `py -3.14 pipeline/crop.py <slug> --at <秒>` 先看候选，再加 `--write` 出图；框不准时用 `--box x,y,w,h` 手动指定。
   **裁切只看一块**：宽度控制在 1000px 以内（放进 860px 正文才会被放大），不要截整条 1920 宽的横带——
   那样在页面里就是一根细线，放大也读不了。**按需生成**：不需要抄参数的步骤可以不裁。
6. 代码与参数**只写从截图里真读到的**；读不清写"画面太小，未展开"，不要补一个"合理"的值。
7. 同一参数不要在正文反复出现——正文说一次，其余进「参数总表」。
8. 不写"多练练就好"这类空话；要么给判据，要么不给建议。

## 七、写完自检

```powershell
py -3.14 pipeline/finish.py <slug>     # 验收（= note_audit）+ 导出
py -3.14 pipeline/quote_check.py <slug>  # 引文出处体检
```

FAIL 必须清零；WARN 要能说清为什么留。新包（`note_schema >= 2`）多查五项：
图注是否按内容写、图在步骤内、图带跳转、裁切图成对、可读性（重复句 / 转述词 / 参数集中度）。

- [ ] 每个 `###` 小节都有时间
- [ ] 每张图都在 `assets/` 里真实存在，且嵌在对应步骤里
- [ ] 每条结论有时间戳
- [ ] 每张图都有按内容写的图注；带时间的标题都有跳转链接
- [ ] 参数集中在总表，正文不重复堆
- [ ] 「置信度与缺口」写了，猜测没有写成事实
- [ ] 附录采样口径抄自 BRIEF，与 `research.json` 对得上
