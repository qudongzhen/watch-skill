# 实施方案：字幕"去滚动"（解锁平台自动字幕）

> 来源：`docs/plan-fetch-subtitles.md` §3.3（2026-10-31 补验：YouTube 自动字幕是滚动行）
> 状态：**已实施并验证**（2026-10-31）；同时挖出并修掉 D18 链路上的三个真 bug（见 §2.5）
> 前置：D18；现有 8 篇笔记；`selfcheck` 20 项、八套 `test_*.py` 全绿

---

## 0. 为什么要做

联网补验时量到：同一个 9 分钟视频，YouTube 自动字幕解析出 **506 段 / 5357 词**，而 whisper
只有 **245 段 / 1828 词**。多出来的 3 倍不是识别出的字多，而是 **VTT 的滚动行**：

```
00:00:01.9  In my game Lexy's Spell, I have a lot of
00:00:02.0  In my game Lexy's Spell, I have a lot of UI, and pretty much everything is
00:00:03.8  UI, and pretty much everything is
```

每一句都把上一句一起带上。现有 `subs.merge()` 只合并"相邻且**文本完全相同**"的 cue，
接不住"逐句变长/变短"的滚动，所以自动字幕现在**根本不能用**——这也是 D18 决定
"自动字幕默认不接"的直接原因。

去滚动是解锁这条路线的唯一前置。做完之后能回答的问题：自动字幕到底比 whisper 准多少？
值不值得为它加一条 opt-in 通道。

## 1. 做法

### 1.1 核心：剪掉"与上一条尾部重叠"的前缀

新增 `subs.strip_rollover(prev, cur, min_overlap=4)`：在 `prev` 的后缀与 `cur` 的前缀之间找
**最长公共段**，把 `cur` 里重复的那一段剪掉，返回新增文本。

- 用**最长**重叠而不是第一个匹配：`A B` → `B` 的场景里，短匹配会把 `B` 留成重复内容。
- 允许最短 4 个字符：中文 4 字、英文约 1 个词，低于这个长度的重叠高度可能是巧合
  （`… the code` / `code again` 会误剪）。
- 剪完再 `strip()` 空白与句首标点（滚动行换行处常留一个空格或逗号）。

### 1.2 只对"看起来是滚动"的字幕动手

`subs.looks_rolling(segs, min_overlap=4, ratio=0.25)`：统计相邻 cue 对里"存在 ≥4 字重叠"
的比例，**≥25% 才认定是滚动字幕**。

这条闸门是本次最重要的安全设计：正常字幕（人工 SRT）里偶尔也会有句尾与下句开头撞词，
不做判定就剪会**静默吃字**。宁可对一份真滚动字幕漏剪（退化成现状：重复但可读），
也不要对正常字幕误剪（静默丢内容）。

### 1.3 接线

| 位置 | 改动 |
|---|---|
| `subs.parse_cues()` | 末尾从 `merge(segs)` 改成 `merge(deroll(merge(segs)))`；`deroll` 内部先过 `looks_rolling` 闸门，不满足就原样返回 |
| `pipeline/test_subs.py` | 新增：滚动样本被压成 1828 词量级的正常文本；正常字幕**逐字不变**（幂等）；重叠 <4 字不剪；全重复 cue 被剔除且时间并入上一条 |
| `run.py --auto-subs` | **opt-in**：加上才允许 `--write-auto-subs`；默认仍只拿人工字幕（自动字幕是机器文本，不自动信任） |
| `meta.subtitles` / `research.json` | 记 `source: "auto-subs"`，BRIEF 写清"平台自动字幕（机器生成）" |

默认不开：自动字幕不是作者原文，质量待量；把它做成开关，谁要谁开。

## 2.5 接通过程中挖出的三个真 bug（都在 D18 那条链路上）

1. **`--list-subs` 会让下载一个字都不落**。D18 起字幕命令里就一直带着它（本意是顺手拿语言表），
   而它是"只列出、不下载"模式：命令返回 **0**、没有报错、也没有文件。也就是说
   **"拿到站点字幕就用它"这条路此前从未真正跑通过**（B 站一直只有弹幕，所以没暴露）。
   修法：下载与列举拆成两条命令，只有没下到时才列一次语言表来分类原因。
2. **`--convert-subs srt` 需要 `--ffmpeg-location`**。不给的话 yt-dlp 打印
   `has no subtitles` 而不是"找不到 ffmpeg"——误导性极强。现在统一带上 `tools/ffmpeg/bin`。
3. **多语言一起要时，一条 429 会把整批判失败**。`zh-Hans`（机器翻译轨）偶发 429 时，
   默认行为是整批 `has no subtitles`，连已经拿到的 `en` 都丢。加 `--ignore-errors` 解决。

三条都是"跑起来才发现"的类型：单测用替身 `ytdlp_soft` 永远测不出来，只有真联网跑才暴露。

## 4. 这一轮不做的

| 风险 | 缓解 |
|---|---|
| 误剪正常字幕的句尾撞词 | `looks_rolling` 闸门（≥25% 相邻对重叠才动手）+ 最短 4 字 |
| 自动字幕本身是机器文本（可能不如 whisper） | 默认关；开了也只在 `meta` 里标注来源，不改"作者原文"的默认路径 |
| 中英混排时"字符重叠"不等于"词重叠" | 只做**前缀后缀**比对，不做词切分；误伤由闸门兜住 |
| 去滚动后时间码变粗（多条并一条） | 保留最早 start 与最晚 end，不丢覆盖区间 |

## 4. 这一轮不做的

- 不给自动字幕做"翻译轨质量评估"（同一视频有 `zh-Hans` 机器翻译轨，本次只比 `en`）。
- 不把自动字幕设成默认：默认仍是"人工字幕 → whisper"。
- 不改 `hardsub.py` / `asrfix.py`；本方案只碰 `subs.py` + `run.py` 的一个开关。
