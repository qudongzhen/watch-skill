模块与文件寿命看 `docs/PROJECT_MAP.md`，写作看 `pipeline/NOTE_CONTRACT.md`，
决策索引看 `DECISIONS.md`。

## 约定

1. **方案文档定稿后不再改写历史**。后续结论用两种方式挂上去：顶部状态行、
   或在被否决的段落后面加一段引用块（例：`--windows` 那一段）。
2. **否决比采纳更重要**。每个被否掉的方案都要留下"为什么"和可复现的数字，
   否则下一个人会把弯路再走一遍——这条规矩来自 `DECISIONS.md` 的开头。
3. **文档里提到的开关必须真的存在**。`pipeline/check_docs.py` 会扫这些文件，
   被 `selfcheck.py` 调用；历史文档里提到已删除的开关，那一行要有"否决/删掉/原来"之类的字样，
   否则自检会红。
4. 数字要能复现：方案里的实测表都注明了脚本（通常在 `work/tmp/`，按约定可整目录删）。
5. **会变的数字只进这里，不进 README/AGENTS**。体积、项数、耗时这类值随笔记与版本变化，
   写进使用手册等于让下一个人每天改文档；手册只写**规则和命令**（"怎么看""什么时候清"），
   实测值留在带日期的方案/评审里（本目录、`DECISIONS.md`）。
