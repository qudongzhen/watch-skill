## 1. 起点：我原本想做"分窗"，评审把它否了

原方案：>20 分钟的长片按 5 分钟一窗出 4×4 图版，**替换掉"每章一张 3×3"**。
理由看起来是双赢——p2 从 9 图/97 帧变成 7 图/121 帧。

评审用三条把它否掉了，每条我都复核过：

| 否决理由 | 数据 |
|---|---|
| **"帧更多"是拿分辨率买的** | 固定像素预算下 `帧数 × 每格面积 ≈ 常数`：4×4 每格 187×106 = 19.8k px，3×3 是 250×140 = 35.0k px（**−43%**）。p2 总像素 2.96 → 2.35 Mpx（−20%）。而且 187px 跨过的是"能看出这帧在讲什么"的台阶，不是 25% 的渐变 |
| **破坏了笔记契约** | `NOTE_CONTRACT` §一 的范例是"每章一张 `assets/grids/s01/grid.png`"、§六 教程体要求"每个步骤必须有一张图"。窗口化后 `sections[].image = None`，契约与 BRIEF 骨架同时悬空；实测 p2 有 **5/8 段横跨两个窗**，`段→W0M` 的一对一箭头会让人漏看半段 |
| **收益长在别处** | 8 篇成品笔记里 **7 篇引用 0 张图版**（45 处引用全是 `assets/stills/`）。所以"读者无法判断第 12 分钟该不该细看"这个动机是错位的——图版只在**写笔记那一刻**有用 |

还有一条我自己算出来的：分窗不是"更匀就更密"，p1 分窗后整体变稀（18.9 → 20.2s/帧），
5/8 段本来比窗口更密。**用分辨率换帧数、换掉一个和契约对齐的结构，不划算。**

## 2. 改道：三件更小、更好、不动契约的事

### 2.1 长片 ≤3 个切点时，章节自动退化为等分

原来按切点分：p2（0 切）被劈成 **118 / 236 / 355s** 三段一样的段落，段内采样间隔跑到
**44.3s/帧**；而 355s 那一段其实讲的是同一件事的一串操作。

现在：`dur > 900s` 且切点数 ≤3 → 按 `ceil(dur/180)` 等分（上限 `--max-sections`）。
p2 变成 **8×192s**，p3 变成 **7×160s**。`--no-auto-even` 保留旧行为。

**为什么这是对的做法**：`DECISIONS.md` D12 早就承认"每条自成一体、几乎无硬切的素材，
按切点分段等于没分段，`even` 才是对的"——只是过去要人记得敲参数。现在变成默认。

### 2.2 每段格数按段长给（盒子不变，格数变）

```
段长 ≤150s → 3×3（9 格）
     ≤300s → 4×4（16 格）
     更长 → 5×5（25 格）
```

**关键事实**：图版 token 是**按张**计价的（756px 的 3×3 与 5×5 同价），所以**加格子不花钱，
加图才花钱**。原方案把钱花在"多一张图"上，改道后花在"同一张图里塞更多格"上。

实测 p2：**图数不变（9 张），帧数 97 → 153，段内间隔 14.8–44.3 → 12.8s 均匀**。

### 2.3 `pipeline/zoom.py`：按需密集图版

```
py -3.14 pipeline/zoom.py <id> --at 62 --window 8          # 25 帧 / 0.33s 一帧
py -3.14 pipeline/zoom.py <id> --t0 300 --t1 330           # 30s / 25 帧 = 1.25s 一帧
```

- 产物落 `notes/<id>/assets/grids/zoom_<t0>_<t1>/`，带 manifest，与既有图版同契约；
- 只**调用** vendor 的 `vw.py grid`，不改 vendor（D9）；
- 越界行为：`t0` 超出素材 → 明确报错；`t1` 超出 → 收到片尾并提示；帧数超区间可用帧数 → 自动下调；
- BRIEF 里加一节告诉写作者什么时候用它。

## 4. 否决清单（别再走一遍）

- **分窗替换分章**：见 §1，三条否决理由都是可复现的。
- **`dur > 20min` 当触发条件**：p1 分窗后反而变稀，p3 最坏段 32.6s/帧和 p1 同病——时长是错的代理量。
- **尾窗 "37s 保留 16 格"**：为 590 字的片尾告别付一整张图，还把"平均间隔"的数字拉好看了。
- **窗口边界吸附切点**：p2/p4 切点 0 个，永远吸不上；`BV1Xdnc6jEbL` 有 21 个合格切点，
  却因为"取最近"（最近那个不合格）而**一条都没吸上**。等分模型下没有边界可吸，规则本身就是多余的。
- **`note_audit` 读的是 `research.json` 的 `images` 字段**：`pipeline/note_audit.py:61` 取
  `grids = research.get("images")`，第 158–175 行拿它做"正文引用的秒数必须落在某张图版的
  覆盖区间内"的可回溯性检查。谁删/改 `images` 字段，这条检查会**静默跳过**，不 FAIL 不 WARN。
  （原文写反成"不读 images、读 grids"，2026-10-31 评审指出后改正。）

## 5. 收尾（三条待办的结论）

1. **图版很少进成品笔记 → 不补**。53 处图片引用里只有 2 处是图版；8 篇的附录反而都写了采样口径。
   强制每章配图版会让交付物体积翻倍（8 张 2.55 MB），读者收益未验证。图版是写作者的草稿纸。
2. **密度积分分格 → 不做**。只影响 2/8 篇，其余 6 篇密度恒为 1；且切点在录屏语料上是噪声
   （154 个"切点"抽帧全是 UI 高亮）。见 `DECISIONS.md` D17 的否决段。
3. **重跑覆盖 → 已修**。`research.json` / `BRIEF.md` 在成品笔记存在时改写 `*.new` 并报差异，
   `--refresh-meta` 才覆盖；同时 BRIEF 里新增机器生成的「取证说明」，附录不再手写。
   见 `DECISIONS.md` D17。
