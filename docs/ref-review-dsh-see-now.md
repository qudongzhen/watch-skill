## 0. 一句话

它是"**让模型实时看你的屏幕**"的插件：把屏幕帧按"变化分"筛出值得看的几张，拼进一张 4×4 图再喂给模型；
我们做的是"**把一段视频拆成可考据的取证包**"。**产品目标不同，但底层要解决的问题高度重叠**——
"哪一帧值得留下、留下来怎么拼、一张图值多少 token"。

## 1. 它的架构（与我们可比的部分）

```
采集(capture.js/scale.js) → 逐帧变化分(cuts.js) → 双判据决定留不留
      → 档位(tiers.js：按"每秒留几帧"定格子大小) → 排布(pack.js：変尺寸 DP 装箱)
      → 出图(sheet.js) → 注入会话(index.js / chat.js / interject.js)
```

对应到我们：

| 能力 | 它 | 我们 |
|---|---|---|
| 帧间差异打分 | HSV 三通道加权差，64×36 网格（`src/cuts.js:9-96`） | 选帧用**拉普拉斯方差**（`pipeline/sharp.py`）；切点用 **ffmpeg `scdet=t=10`** |
| 决定"留哪一帧" | 绝对地板 + 相对尖峰 + 不应期；另加"变化积分"兜底 | 切点分章（`plan_sections`）+ 无切点自动等分（D16） |
| 版面 | 可变档位 + DP 装箱，最大化占用率（`src/pack.js`） | 固定等格：全片 5×5、每段 3×3/4×4/5×5（D16） |
| 成本意识 | 明确算 token（一张 800×450 ≈ 233），并给"多一张图"标价（`binCost=1.02`） | 只粗略记过"9 张图版 ≈ 3100 token"（D2 写的是 756×756 ≈ 346） |

## 2. 值得借鉴（按对我们的价值排序）

### 2.1 ★★★ 无切点长片的"变化积分"分段

**它怎么做**：不只看"这一跳算不算切点"，还累加每帧的变化分；攒够固定额度就落一个采样点：

```
need = 参考强度(4) × fps(12) × integralSeconds(3) = 144
每帧累加自己的分，累够就录、清零
```

关键细节（`docs/调参与实测.md` §四）：阈值必须是**固定绝对值**。他们早先用过
"阈值 ∝ 当前平均变化量"，结果画面动得越快阈值越高，**退化成固定 N 秒一帧**，那个实现被删了。
同一段 24 秒合成片：`integralSeconds=3` 留 7 帧，`1.5` 留 12 帧——"别为了更灵敏随手改它"。

**为什么对我们有用**：我们 8 篇里 **4 篇几乎没有切点**（Blender 教程 p1–p4：0–10 个切点 / 12–25 分钟），
D16 的解是"自动等分"。等分的坏处是**章节边界和内容边界无关**——第 3 段可能从一句话中间切开。
"变化积分"正好补这个洞：没有切点时，按"画面累计变化了多少"选边界，而不是按秒数平均。

**可验证性**：p2/p4 的 `source.mp4` 都在，可以直接算逐帧分数、按积分切 8 段，
把新边界和现有等分边界并排抽帧看——**看边界是不是落在"界面换了"的地方**。成本约 2 分钟/篇。

### 2.2 ★★ 切点判据要"地板 + 尖峰 + 不应期"三件套

README「它是怎么判断"变了"的」写得很清楚：

```
score ≥ cutAbs(12)              // 地板：变化够不够大
score > 2.5 × max(1, 前后帧)     // 尖峰：是不是"一下子"
距上一刀 ≥ 0.4 秒                // 不应期
```

并给了**为什么缺一不可**的实测反例：缓慢放大片段里有一帧 `s=13.6`、邻帧只有 `1.1/1.3`，
**只有尖峰判据时它会被放行**，持续运动就会被切碎；反过来只有地板也不行——一镜到底每帧 4 分，
永远不"跳"。这句话值得抄进我们的 `DECISIONS`：我们现在的切点只有**地板（scdet=10）+ ffmpeg 自带的
场景分数**，既没有尖峰确认、也没有显式不应期（`scdet` 内部有最小间隔，但不是我们的策略）。

### 2.3 ★★ token 成本可以算，不该凭感觉

README 给了公式（按 14px patch 向上对齐成 42px 一格）：

```
tokens = rows × (cols + 1) + 2,   rows=ceil(h/42), cols=ceil(w/42)
800×450 → 233 token
```

用它量我们自己的两种图：

| 图 | 尺寸 | 公式值 |
|---|---|---|
| 全片 5×5 图版 | 765×440 | 11×20+2 = **222** |
| 分段 3×3 图版 | 762×432 | 11×20+2 = **222** |
| 全屏定点截图 | 1920×1080 | 26×47+2 = **1224** |

**结论是比值，不是绝对值**：一张全屏截图 ≈ **5.5 张图版**（按面积比是 6.2 倍，同一量级）。
我们一直强调"读字必须看全屏原帧"，这条量化后可以写成写作纪律：**全屏图只在对字/对参数时贴，
一张全屏换五张图版**。另外它印证了我们"图是按张计价、加格子不加价"的判断（D16 的前提）。

> 注意绝对值的坑：我们实测 9 张图版 ≈ 3100 token（≈344/张）跟公式给的 222 对不上，
> 说明宿主的分词/缩放跟这个模型不完全一致。**只拿它做相对比较**，别写进验收阈值。

### 2.4 ★ 诊断输出：把"差一点过关"的帧列出来

`docs/调参与实测.md` §一：调试窗里"过了七成门槛但没过线"的帧会染成琥珀色，
调 `cutAbs` 时看它们落在多少分，比看曲线估更准。我们目前调 `scdet` 阈值**没有任何工具**，
只有"改完重跑看分段对不对"。最小可做的版本：给 `run.py` 加一个只读的 `--explain-cuts`，
打印"分数 top-N 切点 + 差一点没过线的帧 + 每个切点两侧的分数"。

### 2.5 ★ 一条工程纪律：把"靠巧合"换成显式规则

`src/pack.js:284-298` 自述：旧代码"多箱时只退一帧"**实测是对的**，但正确性依赖
`boostMinFrames=4` 和"4 个 1 档帧装得下一张"两个数字刚好咬住；作者把它换成了
"退到装得下为止"的显式规则，并加了 `stats.overflow` 计数器兜底。

这条对我们有直接映射：**我们的"重跑守卫"曾经也是靠巧合**（路径基准不一致，守卫恒假，D22 才查出来）。
凡是"表面上没事、其实依赖两个常量刚好对上"的地方，都该有显式规则 + 计数器。

## 3. 我实测后**不成立**的部分（别照搬）

它的 `src/cuts.js` 开头写着：

> `scorePair` 照抄 storyboard 的 scan.js …… 同一段测试片它 **9/9 命中、`ffmpeg scdet` 只 4/9**
> （scdet 算亮度类 MAFD，对"同亮度换色"失明）

这个结论**在我们的语料上不成立**。用我们自己的原型 `work/refs/hsv_scan.py`（同一套 HSV 加权差）
在两篇笔记上对 `timeline.json` 里现有的 `scdet=10` 切点做比对：

| 素材 | HSV 切点 | scdet 切点 | scdet 被 HSV 覆盖 | HSV 多出来的 |
|---|---|---|---|---|
| `BV1oi416bERx_p1`（9分56秒，录屏 + 图版讲解） | 169 | 66 | 64/66 | **112 个** |
| `BV1Xdnc6jEbL`（7分06秒，剪辑极密） | 178 | 175 | 167/175 | 28 个 |

- 剪辑密的片子上两者几乎等价（178 vs 175），**"scdet 漏一半"没有复现**；
- 录屏类素材上 HSV 多抓的 112 个，是 **RenderDoc 面板重绘/鼠标高亮**这类"画变了但不是换镜头"——
  对"分章"是噪音。这正好印证 D16 的那条负结果（讲座被 HSV 判出 154 个"切点"，抽帧全是 UI 高亮）。

**所以**：不要替换切点检测；如果要动，动的是 2.1（无切点时怎么分段）和 2.2（判据要不要加尖峰）。

## 4. 不适用 / 明确不做

| 它有的 | 为什么我们不抄 |
|---|---|
| 实时采集（ddagrab/gdigrab/avfoundation）、0.28 核占用 | 我们处理的是"已下载的视频文件"，不是活屏幕 |
| 悬浮窗 + TTS + `say` 通道 + 语音适配器 | 陪看场景；我们的产出是**离线笔记 + 导出件** |
| 变尺寸 DP 装箱（`pack.js` 372 行） | 我们用 ImageMagick montage 等格，可读性与实现成本都更好；等格还能让"第几行第几列→第几秒"直接查 manifest |
| 档位 1..8 与 7 道阈值 | 那是为"每秒留 1~4 帧"的实时密度设计的；我们的图版是"每段一张"，D16 的三档已够 |
| `scene:true` 一帧铺满 | 我们用"定点截图"达到同样目的（全屏原帧），而且带 `pick` 证据链 |

## 5. 建议的下一步（按性价比）

1. **做一次"变化积分分段"的可行性验证**（2.1）：在 `BV1YV411w72F_p2` + `_p4`（都是 0 切点长片）
   上算逐帧分数、按积分切 8 段，抽帧对比现有等分边界。**只出方案与数据，不接进 pipeline**——
   D16 的教训是这类分母级改动要先看证据。
2. **给切点加"解释模式"**（2.4）：`--explain-cuts` 打印 top-N 与"差一点"的帧，让以后调阈值有据可依。
   小而独立，不动主链路。
3. **把 token 公式写进 BRIEF 的成本提示**（2.3）：说明"一张全屏 ≈ 5.5 张图版"，让写作者知道代价。
