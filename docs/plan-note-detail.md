## 0. 差在哪（已核实的四条）

| # | 原因 | 证据 |

| 1 | **有硬字幕却没用**：画面底部有中英硬字幕，我们走 whisper 英文转写，数字与参数名损耗大 | 裁 `len.png` 底部可读 `I'm going to work with is 0.01`；P1 附录写"未烧入画面"（**错**） |

## 1. 目标（可检验，已按评审拆成"自动 / 人工"两段）

| 目标 | 指标（20 分钟教程） |
|---|---|
| 详细步骤 | 一步一件事；每步"怎么做 / 怎么判断 / 坑"三件套 |
| 重点处加密 | 取消均匀采样；**自动候选 ≥8 张**（P1 实测事件只有 11 个，所以候选按事件数封顶） |
| 人工补拍 | 目标总数 = `clamp(ceil(分钟×2), 6, 60)`（20 分钟 ≈ 40 张，40 分钟封顶 60），差额由写作者补拍，BRIEF 写明"还需补拍 N 张"；token 账：60 张 ≈ 7.3 万 |
| 图跟着文字走 | 图嵌在对应步骤内；每张图所在小节带**跳转该秒的链接** |
| 查证 | 不设必填节；描述不清时查官方文档，查到带链接，查不到写"未查到" |
| 可读 | 步骤目录表；无重复句；参数集中在总表 |
| 字数 | 不设上下限；改由"每步 ≥3 条要点"做结构底线 |
| 不倒退 | 时间戳、图、置信度三件套不变；旧笔记迁移清单见 §4 |

## 2. 规则改动

### 2.1 采样：事件驱动 + 预算制（解决"事件爆炸"与"上限截断"）

**取消**均匀分配。扫全片找事件，每个事件一张候选：

| 事件 | 判据 | 成本 |
|---|---|---|
| 冻结段起点 | `probe` 的 freezes | 免费 |
| 语音密度峰 | `silencedetect` 反推的连续说话段 | 免费 |
| 关键词命中 | 现有 `_score`，强命中优先 | 免费 |
| 新界面首现 | 切点后 0.8 秒 | 免费 |
| 字幕文本变化 | hardsub 的字幕带 OCR 变化点 | 3–8 分钟/20 分钟，opt-in |

**三道闸，防止密切口素材爆图**（评审 #4）：

1. **全局去重**：相邻候选间隔 < 5 秒只留一张（不再用"同段 3 秒"）；
2. **每分钟配额**：任一 60 秒窗口内最多 3 张候选；
3. **总预算**：候选总数 = `clamp(ceil(分钟×2), 6, 60)`；超出按"强事件优先（冻结 > 关键词 > 语音峰 > 切点首现）"截断。

**预算与截断要显式**（评审 #1）：`--max-stills` 默认改为 `auto`（按上面公式算），`--max-stills 0` 表示**不截断**；
删除 `pick_stills` 里"超出就等距抽稀"的逻辑，改为按事件优先级丢弃。BRIEF 写明本次预算、实际候选数、需补拍数。

`--focus 6:23,10:21` 人工指定必拍时刻（用 `timefmt.parse_stamps` 解析 mm:ss），优先级最高，且不受预算截断。

**新增开关（尚未实现）**：`--still-events {freeze,speech,keyword,cut,ocr}`、`--focus`、`--target-section-len`。

**分段优先级要写死**（评审"与代码不符 #5"）：`--sections-mode cut` 时，先按切点分，再用 `max_span=120s` 强制劈，
再合并到 `--max-sections`；`--target-section-len` 只在 `cut` 模式下作为"合并目标"（默认 90s），
在 `--sections-mode even` 与 `auto_even`（>15 分钟且切点 ≤3）时**不生效**。

### 2.1b 硬字幕：从"取图信号"升级为"转写来源"（解决评审 #2）

原 v3 只拿 OCR 当取图事件，等于绕过第一号原因。改为：

| 步骤 | 内容 |
|---|---|
| 1 | 教程体默认跑 `hardsub --detect` 定位字幕带（7 帧采样，秒级） |
| 2 | 命中则跑 `--subs-ocr`：按 2 秒/帧 OCR，落 `evidence/subtitles_ocr.md`（**这是新功能，20 分钟素材 3–8 分钟，不是小改动**） |
| 3 | BRIEF 顶部标「检测到硬字幕，参数与菜单名优先按字幕原文」；转写文本与字幕冲突时以字幕为准 |
| 4 | 没有硬字幕的素材，行为不变（走 ASR） |

规模说明：`--detect` 已有；`--subs-ocr` 的时间序列与落盘是新写，`hardsub.py` 约 +120 行。

### 2.1c 图版降级为"定位工具"

| 素材 | 图版张数 |
|---|---|
| 教程 / 录屏（20 分钟） | 全片 5×5 **1 张** + 每 10 分钟 1 张 → 共 3 张 |
| 口播 / 观点（画面同质） | 维持全片 1 + 每段 1（此时图版是"替代看片"的主力） |
| 长片 >30 分钟 | 全片 1 + 每 10 分钟 1，**上限 5 张** |
| 短视频 <5 分钟 | 只给全片 1 张 |

BRIEF 的"图版清单"换成**候选帧表**（时刻 / 事件类型 / 所属段 / 跳转链接）。
候选帧可能落在段外（评审 #6）：表里按"最近事件所属段"归档，保证写作者能把图对到步骤。

### 2.2 图：跟着文字走，带跳转（修正 v3 的错误断言）

**现状**（评审"与代码不符 #1"）：`link_at()` 只有一条规则 `{url}{sep}t={int(sec)}`，
没有 `?p=N` 拼接、没有 YouTube `&t=秒s`、没有 `#t=秒` 兜底。它能用是因为 B 站与 YouTube 都认 `t=秒`；
分P 的 `p` 来自 `webp_url`，URL 里没有 `p` 时跳转会落到 P1。

改为新增 `jump_url(url, sec)`（`run.py`）：

| 平台 | 生成规则 |
|---|---|
| B 站 | URL 已有 `p=` 则 `&t=秒`，没有则补 `?p=<从 URL 解析>`（解析失败就不补，并在 BRIEF 里提示） |
| YouTube | `&t=秒`（`youtu.be` 用 `?t=秒`） |
| 其他 | `#t=秒` |

| 规则 | 内容 |
|---|---|
| 位置 | 图必须嵌在对应步骤内部，禁止集中在开头/结尾 |
| 尺寸 | 参数/代码类一步配两张：全屏 + 裁切放大（`still.py --crop --zoom` 已有） |
| 跳转 | 每张图所在小节必须有该秒跳转；**这是新工作**（现在 BRIEF 的 stills 列表只有 mm:ss，没有链接） |
| 数量 | 按 §1 的预算；token 账：24 张全屏 ≈ 2.9 万 token + 3 张图版 ≈ 3.2 万 |

### 2.3 契约：放宽字数，补结构底线

| 项 | 现在 | 改为 |
|---|---|---|
| 字数 | 800–1800，`600+160×步骤` | **取消**上下限，篇幅只输出数字 |
| 步骤要点 | ≥2 条（WARN） | **≥3 条（FAIL，教程体）**——用结构底线替代字数底线（评审 #5） |
| 每步判据 | 无 | 教程体每步须出现"怎么判断/判据/自检"之一（WARN） |
| 图数 | 每步 ≥1（FAIL，现状） | 不变 |
| 步骤粒度 | 未规定 | 一步一件事 |
| 目录 | study 才有大纲 | 教程体加步骤目录表（步骤名 + 时间区间 + 跳转） |
| 外部核实 | 无 | 不设必填节；就地写 `（依据：[文档](链接)）`；无链接不得声称"官方如此" |

**旧笔记不迁移**（2026-11-11 决定）：新规则只对**新取证包**生效，靠 `research.json` 里的 `note_schema` 版本号区分
（`run.py` 升级后写 `note_schema: 2`；没有该字段 = 旧包，沿用现行规则）。这样 12 篇旧笔记既不补也不改，跑验收不会变红。

### 2.4 验收：`note_audit` 改动

| 检查 | 现在 | 改为 |
|---|---|---|
| **适用范围** | 全库一套规则 | **按 `research.json.note_schema` 分流**：缺字段 = 旧包，走现行规则；`>=2` = 新包，走下列新规则 |
| 篇幅 | 上下限 WARN | **不判红黄**，只输出字数与图/千字密度 |
| 步骤配图 | 每步 ≥1（FAIL） | 不变 |
| 步骤要点 | ≥2（WARN） | **≥3（FAIL，教程体）** |
| 每步判据 | 无 | 缺"怎么判断/判据/自检" → WARN |
| 图片位置 | 无 | 图不在 `###` 步骤内 → WARN（分体例：study 允许大纲图） |
| 图配跳转 | 无 | 步骤内有图但无 `?t=`/`&t=`/`#t=` 链接 → WARN（**旧笔记 8 篇会全中，见 §4 迁移**） |
| 可回溯性 | 按图版区间 | 按**图版 ∪ 截图**区间并集 |
| 重复句 / 转述词 / 参数集中度 | 无 | 各自 WARN |
| 外部链接 | 无 | 出现 http 链接时校验格式；不强制 |

## 4. 验证：P1 对照（已跑）

**实施结果（2026-11-12，`BV1YV411w72F_p1` vs 新规则重写的 `_v2`）**：

| 指标 | v1（旧规则） | v2（本方案） | 外部 docx |
|---|---|---|---|
| 步骤 | 8 | **14** | 17 |
| 正文汉字 | 1,594 | **2,797** | 3,128 |
| 图 | 8 | **14** | 13 |
| 跳转链接 | 0 | **28**（目录 14 + 步骤 14） | 0 |
| 表 | 1 | 3（目录/参数/排错） | 5 |
| 参数精确值 | 4 | **10+**（0.05/0.01/0.052/0.15/0.75/0.3/8 点…） | 10 |
| 验收 | 旧规则 0 FAIL | **新规则 0 FAIL / 0 WARN（16 项）** | — |
| 文本来源 | whisper（英文） | 硬字幕 OCR（366 段，中文行） | 硬字幕 |

结论：**规则改对了**——同一条素材，字数与步骤接近外部 docx，且多了跳转与机器验收。
但也要承认差距：图文密度（5.0 张/千字）仍低于对方，"一步一件事"还做得不够细；这两项靠后续补拍与写作习惯，不是脚本能强制的。

### 原计划指标 vs 实际

| 指标 | 目标 | 实际 |
|---|---|---|
| 步骤数 | ≥12 | 14 ✅ |
| 图数 | 24–40 | 14（自动 16 可用 + 手工补拍 2，未补满 40）⚠️ |
| 参数精确值 | ≥10 | 10+ ✅ |
| 图带跳转 | 100% | 100% ✅ |
| 验收 | 0 FAIL，WARN ≤2 | 0 FAIL / 0 WARN ✅ |

图数没到 40 是**写作侧的取舍**：14 步各一张已能覆盖，硬凑到 40 会稀释；这条按"预算不是配额"理解更合理。

**旧笔记：不补、不管。** 12 篇一律保持原样，靠 `note_schema` 门控让它们继续走旧规则（跑验收不变红）。
实施清单里的"旧笔记迁移"一行作废；只在新取证包里启用新规则。

## 5. 风险与否决

| 风险 | 处理 |
|---|---|
| 密切口素材仍可能爆图 | 三道闸（8 秒去重 / 每分钟 2 张 / 总预算 24） |
| 硬字幕 OCR 慢且可能认错 | opt-in 到"检测到字幕带"才跑；OCR 文本与 ASR 冲突时以字幕为准但标置信度 |
| 取消字数上限后写水 | 每步 ≥3 条要点升 FAIL + 判据检查 + 三条可读性 WARN |
| 从严规则误伤旧笔记 | **用 `note_schema` 门控**：旧包不跑新检查，不补不改 |
| 取消按段取图后 `stills[].section` 为空 | BRIEF 用"最近事件所属段"归档 |

**明确不做**：图像内容识别（D5）、自动改写正文（D1）、为凑长度扩写、目前阶段的 docx 导出（需另装 pandoc，见 §7-21）。

## 6. 落地顺序

1. **契约 + 验收 + 迁移**同一提交（先跑 12 篇回归，确认只有预期内的变化）；
2. **取样**（事件驱动、三闸、预算、`jump_url`）；
3. **硬字幕 OCR**（`--subs-ocr`）；
4. P1 重跑对照 → 达标后推广 P2–P4；
5. 文档统一整理（README / AGENTS / FEATURES / docs/README 索引）。
