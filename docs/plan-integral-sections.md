## 0. 要解决的具体缺陷

D16 的 `auto_even` 对"长片 + 切点极少"的素材**按时间等分**（`run.py:352-353`）：
`dur > 900 且 cuts ≤ 3` → `even(ceil(dur/180))`。4 篇 Blender 教程的实际情况
（注意：**只有 `p4` 的 `sections` 真来自等分**，p1–p3 是旧版 `plan_sections` 留下的不等长分段，
这一点是跑完数据才发现的，见 §6）：

| 笔记 | 时长 | 切点 | 现存分段（`research.json`） | 段长 |
|---|---|---|---|---|
| `BV1YV411w72F_p1` | 1212s | 10 | 8 段（切点派生） | 114–230s |
| `BV1YV411w72F_p2` | 1537s | **0** | 8 段（旧逻辑，不等长） | 118–355s |
| `BV1YV411w72F_p3` | 1119s | 2 | 8 段（切点派生） | 106–261s |
| `BV1YV411w72F_p4` | 767s | **0** | 7 段（等分） | 110s ×7 |

问题不在"段数多少"，而在**边界落在哪里**：等分边界与内容无关，一段可能从一句操作讲到一半切开，
读者按"第 3 段"去看图版时，图里前后是两个不相干的操作。

## 1. 做法：按"累计画面变化"而非"秒数"切

定义每帧变化分 `s[i]`（HSV 三通道加权差，64×36 网格；与 `work/refs/hsv_scan.py` 同一套）。
累计 `C(t) = Σ s[i]`。把 `C(dur)` 等分成 N 份，边界取在每个 1/N 分位点上——
**"变化一样多"的地方就是边界**，而不是"时间一样长"的地方。

- 需要**最小段长**约束（≥60s）和**最大段长**约束（≤300s），与现有一致；
- 试两种积分源：① 原始分数；② EMA 平滑后（α=1/6，参考 `tiers.js` 的 smoothing）——
  录屏素材里鼠标/光标的小抖动会累积，平滑可能更稳；
- 对照组：现有等分边界。

## 2. 度量：边界"值不值"

对**每一条边界**算一个**跨边界差**：

```
cross(b) = score( mean(frame[b-5s..b-2s]) , mean(frame[b+2s..b+5s]) )
```

即边界两侧各取 3 秒平均帧，再算 HSV 加权差（0–255）。含义直白：**这里真的是"换了一个画面"吗**。
再统计：

| 指标 | 含义 | 期望方向 |
|---|---|---|
| `median(cross)` | 边界整体质量 | 越高越好 |
| `quiet%` | `cross < 6` 的边界占比（"边界两侧几乎没变"） | 越低越好 |
| `min/max 段长` | 是否出现极端短段/长段 | 不能比等分更差 |
| `cuts 命中` | 边界落在真实切点 ±1.5s 内的比例 | 只作参考（这批素材切点≈0） |

## 3. 判定标准（先写死，避免事后找理由）

- **采用**：积分分段的中位跨边界差 ≥ 等分的 **1.5 倍**，且 `quiet%` 下降一半以上，且段长仍在
  `[60, 300]` 内；
- **部分采用**：中位提升 1.2–1.5 倍 → 只把它做成 `--sections-mode integral` 的可选项，不改默认；
- **不采用**：提升 < 1.2 倍或出现 3 倍以上长短差 → 写进 `DECISIONS` 当负结果，`auto_even` 不动。

## 6. 实测结果（2026-11-02）

度量：每条边界取两侧各 5 秒平均帧算 HSV 加权差（0–255）。另跑"随机挑 20 个非边界时刻"的
同口径值做基线，两者相除得到**倍数**——抵消"这段素材到处都在变"。

**先纠正一个前提**：我开始以为"现有分段 = 等分"，跑完发现只有 `p4` 是等分；`p1`/`p2`/`p3`
的 `sections` 是**旧版 `plan_sections` 留下的**（段长 118–355s 不等）。所以对照里加了一行
`等分(现)`——那是**今天的代码**会对这条素材给出的结果。

| 素材 | 分法 | 边界差中位 | quiet | 段长 |
|---|---|---|---|---|
| `p2` 1537s / 0 切点 | 现有（旧，不等） | 6.9 | **3 of 7** | 118–355s |
| | **等分（现）** | 12.4 | 0 of 7 | 192s ×8 |
| | 积分 | **20.7** | 0 of 7 | 125–259s |
| `p4` 767s / 0 切点 | 现有 = 等分 | 10.5 | 0 of 6 | 110s ×7 |
| | 积分 | 12.1 | 0 of 6 | 73–176s |
| `p1` 1212s / 10 切点 | 切点派生（现） | **27.7** | 1 of 7 | 114–230s |
| | 积分 | 22.8 | 1 of 7 | 75–229s |
| `p3` 1119s / 2 切点 | 切点派生（现） | **19.1** | 1 of 7 | 106–261s |
| | 积分 | 7.4 | 2 of 7 | 76–201s |

（EMA 平滑版与原始分数几乎一样，p2 上 20.7 vs 20.7、p4 上 12.1 vs 12.1，所以**不用平滑**。）

**三条结论**：

1. **比今天的等分略好，但没到"换掉"的程度**：`p2` 中位 12.4 → 20.7（**1.67×**），
   `p4` 10.5 → 12.1（**1.15×**）。按 §3 的判据（≥1.5× 且 quiet 减半）只能算"部分采用"：
   `p2` 达标、`p4` 不达标，且 quiet 本来就都是 0（**没有"边界落在死寂处"的证据**）。
2. **旧版分段确实有坏边界**：`p2` 的旧分段有 **3/7 条**边界两侧几乎没变（中位 6.9，比随机时刻还低）。
   这个缺陷是真的，但**今天的等分已经把它修掉了**（12.4、quiet 0）——也就是说，
   这一轮真正该修的 bug 可能早就被 D16 修掉了一半。
3. **千万别拿它替换切点分段**：`p1`/`p3` 有真切点时，切点派生边界的跨边界差是积分的
   1.2× / 2.6×。切点就是"画面真的换了"，积分只是"攒够了变化"，后者必然更钝。

## 7. 建议：先不接，留作 opt-in（负结果为主）

按 §6，**默认路径不动**（等分 → 保持等分）。理由：

- 收益只有 1.15–1.67×，代价是**段长从"整齐的 192s"变成"125–259s 不等"**——
  而段长直接决定图版覆盖区间和"段内间隔"；读者按段查图时，不等长更难对账（D16 选等分就是为了可预期）；
- 两个样本一个达标一个不达标，样本量不足以改默认值；
- 我们真正的痛点是"切点太少"，而积分法本质上只是**把等分变聪明一点**，并没有创造出结构。

**如果以后要接**，按这个形状接（约 30 行）：只改 `auto_even` 分支（`run.py:352-353`）与
`len(bounds)<3` 那一支；保留最小段长 60s；新增 `--sections-mode integral` 开关，
让"想要边界贴内容"的人自己开；**默认仍是等分**。原型与度量在
`work/refs/integral_sections.py`（`work/` 按约定可整目录删——真删了也能照 §1 的算法与 §2 的度量重建，
参数只有三个：64×36 网格、HSV 加权差、最小段长 60s / 最大段长 300s）。
