## 2. 四块新能力，逐块对我们的判断

### 2.1 站点字幕轨（`src/subtitles.js`）★★★ 值得做

**它解决什么**：B 站的字幕是**独立轨道**，下载下来的 mp4 里通常没有，所以他们以前读容器内嵌流永远拿不到，
只能退回 ASR。而站点字幕是作者自己写的：**不烧 CPU、不错字、带准确时间码**。

**坑（文档里明确写了）**：B 站字幕要登录；没登录时 yt-dlp 只给弹幕，并警告 "Subtitles are only available
when logged in"。所以必须把"没有字幕"和"有字幕但要登录"分开。

**对我们**：我们的链路是"下载 → whisper"，完全没有尝试站点字幕。而我们的痛点恰恰是转写错字
（已实证 8 处：`寒暑→setter`×3、`案号→暗号`×2、`二低/描编/九公格`）。若站点有 CC，能一次性消掉这类错。
工作量：半天（`fetch()` 加 `--write-subs --sub-langs zh-Hans,zh-CN,zh,en`，读 `.vtt/.srt` 走既有
`asrfix` 路径）；风险：需要登录 cookie，失败要能静默退回 ASR。

### 2.2 竖屏下载的坑（0.4.0 修复）★★★ **我们正踩在边上**

**它的记录**：yt-dlp 把 9:16 视频报成 `360x640 / 480x852 / 720x1280`，`height` 是**长边**，
于是 `bv*[height<=480]+ba` 一条都匹配不到，直接 `Requested format is not available`。
修法：选择器末尾加无过滤兜底 `.../bv*+ba/b`，并按 `res:`（yt-dlp 的短边指标）排序。

**我们的现状**：`pipeline/run.py:117` 正是 `-f "bv*[height<=1080]+ba/b[height<=1080]"`。
我们的竖屏样本 `BV1Xdnc6jEbL` 是 **480×852**（height=852≤1080），**侥幸通过**；
但只要遇到 1080×1920 的竖屏，就会整条下载失败。
工作量：一行（加兜底 + `-S res:1080`），风险低。

### 2.3 硬字幕 OCR 校正（0.4.4）★★ 可做，但要引依赖

**它怎么做的**：先用三张全分辨率帧**定位字幕带**（约 3 秒），之后每行只对该横带裁切 OCR、
**不做检测**（0.26 秒/行，而不是 3.1 秒）；只有 OCR 覆盖 ASR 字符 **≥60% 且同序**时才替换，
并把匹配段裁齐避免把相邻行带进来。本地跑，**零额外 token**（对比：让模型逐帧读字幕约 34,500 token）。

**对我们**：我们的笔记里已经出现手工版（"顶部字幕逐帧读过，纠正了二低/描编/九公格"）。
自动化能把这件事从"人肉回看"变成"每次都有"。但需要 `rapidocr-onnxruntime`（新依赖，`install_pydeps` 可装），
且中文字幕带的定位要按我们的素材重调。工作量：1–2 天。

### 2.4 陪看（`video_watch` / CDP + SMTC）✗ 不适用

通过浏览器的 `<video>.currentTime`（CDP，20ms 往返）或 Windows SMTC 读"你看到第几秒"，
再按节奏叫醒会话陪你聊。文档里两个实测结论挺硬：SMTC 的 `Position` **只在事件时刷新**（两次刷新隔过
143 秒 / 216 秒），以及 Chromium 用默认 profile 启动时 `--remote-debugging-port` **会被静默忽略**。
但我们是**离线笔记**链路，不需要实时位置——不借鉴。

## 3. 顺手看到的两个工程习惯

1. **"声明了、校验了、但没接线"**：0.4.4 修了一个 bug——`video_zoom` 的 `minGap` 在 tool-spec 里声明、
   在 validator 里校验，但 `index.js` 逐字段拼装参数时漏了它，于是每次 zoom 都跑 1.2 秒的默认值。
   我们的 `check_docs.py` 只防"文档提到不存在的开关"，**防不住这一类**。可加一条冒烟测试：
   对每个工具参数，用"极小值/极大值"各调一次，断言输出确实变了。
2. **CHANGELOG 每条带实测数字**（"9 → 21（真值 23）"、"0.22–0.27 → 0.08–1.18"）。
   这比"修复了若干问题"有用得多，也正好是我们 `DECISIONS.md` 的写法。

## 4. 建议（按性价比）

| 顺序 | 做什么 | 为什么 | 工作量 |
|---|---|---|---|
| 1 | 下载格式串加兜底 + `-S res:` | 竖屏 1080p 现在会整条失败；我们已有 1 个竖屏样本，只是碰巧够小 | 10 分钟 |
| 2 | 站点字幕优先 | 一次消掉同音错字，且省掉 whisper 的 1–4 分钟 | 半天 |
| 3 | 硬字幕 OCR 校正 | 覆盖"没有 CC 但有硬字幕"的绝大多数中文教程 | 1–2 天 |
| — | 陪看 / CDP / 两级取流 | 离线笔记用不上；两级取流的收益（扫描用 360p）抵不过多一次下载 | 不做 |
